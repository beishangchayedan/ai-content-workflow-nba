# 从需求到交付的统一工作流

适用于需要事实核验、视觉模板和批量交付的内容项目。先把交付口径说清楚，再让 AI 执行具体步骤。工具或模型可以更换，事实来源、人工决定和验收结果必须留下。

## 角色分工

| 角色 | 负责什么 | 不交给该角色单独决定的内容 |
| --- | --- | --- |
| 项目负责人 | 选题、受众、内容判断、规则确认、审美选择、最终验收 | 不凭主观满意代替事实和文件检查 |
| AI 助手 | 整理候选来源、提取资料、生成结构化草稿、实现工具、执行校验 | 不自行确认未经核验的事实、素材授权或业务成绩 |
| 程序与检查工具 | 固定公式、批量渲染、命名、数量与尺寸检查、保存一致性 | 不替代人的内容判断与授权判断 |

## 01 明确制作单

**输入：** 主题、受众、平台和已有成果。填写 [任务模板](../templates/production-brief.md)。

**必须确定：** 项目范围、节点口径、输出数量及尺寸、参考模板、数据截止日期、允许修改的文件、必须保留的用户修订、公开还是内部使用。

**输出：** 一份有实际项目内容的制作单，以及唯一任务工作区。空检查单不能当作通过。

## 02 建立来源与素材登记

- 用英文名或稳定 ID 确认对象，不能只靠中文译名或模型记忆匹配。
- 每条关键事实记录来源页面、访问日期和支持的具体结论；对重要结论交叉核验。
- 把「事实」「编辑判断」「用户手动决定」分别标明，不把主观评分包装成客观事实。
- 图片另记作者、拍摄事件、来源 URL、文件哈希、裁切和许可范围。能下载不等于可公开再分发。

**通过条件：** 对象无歧义；缺失、冲突和授权待定项明确。资料不充分时缩小结论或保留待核验状态。

## 03 固定规则，生成结构化草稿

**输入：** 已核验资料与确认过的模板。

**输出：** 可追溯的内容数据、评分/计算规则、版本标识和素材映射。每项例外记录原因与决定来源。

评分公式、显示等级和图形半径分别处理，避免为了画面好看反向改动分数。复用成熟实现；只修改本轮明确有问题的部分。

## 04 小样与人工审核

选取首节点、峰值或极端值、异常裁切各一例。审查事实、文字、数据、视觉和素材是否一致。

人工改动必须成为可恢复的修订。下一次 AI 生成前先读取有效修订，不能用初始基线覆盖用户当前成果。

**通过条件：** 小样检查通过、人工争议已有处理结论，才进入批量阶段；未通过时只修问题相关范围。

## 05 按清单批量生成

按固定顺序、文件名和尺寸输出，只处理新增或实际变化的节点。任务结束时将实际文件集合与预期清单比对，而不只看命令是否运行成功。

生产案例采用每节点三张面板，A1 能力 → B2 缺陷精神 → C3 正面精神；新题材可以换维度与版式，但要先写入制作单。

## 06 验证完整操作链

| 检查 | 要看到的证据 |
| --- | --- |
| 静态产物 | 实际数量、命名、尺寸、格式、引用关系正确 |
| 视觉 | 打开最终尺寸成品，确认文字、标签、裁切与数据 |
| 编辑与保存 | 修改后读回文件，刷新以及关闭重开仍恢复相同内容 |
| 冲突与故障 | 旧版本写入被拒绝；失败后恢复至保存前的文件集合与字节 |
| 授权 | 缺少必要许可时，公开/商业导出在创建输出前停止 |
| 保护范围 | 其他项目及不在范围内的用户修订保持原哈希 |

测试报告写明本轮版本、输入、执行方式和覆盖范围。旧报告绑定的文件已变化时，不能继续引用旧 PASS 证明新版本。

## 07 发布、归档与收尾

先确认实际发布内容的授权及隐私，再发布。保留必要来源、关键决定、用户修订、验收结果和交付索引；删除已确认失效的重复渲染、临时下载及浏览器工作区。

清理前验证精确路径与受保护文件，清理后记录实际文件数、逻辑字节数和保护哈希。磁盘释放量若未实测，就不要拿文件逻辑大小冒充。

## 节省成本的执行方式

只检索缺口，合格素材立即冻结；复用固定模板和已有实现；独立资料任务可以并行；先小样后批量；改动范围决定回归范围。没有统一耗时基线时，不声称节省了某个百分比。

## 演示实现的边界

公开演示只实现：合成数据编辑、重新复核、授权门禁、浏览器保存恢复及 JSON/PNG 下载。它没有生产系统的文件事务、哈希修订链、跨窗口冲突恢复或批量渲染引擎。演示中的来源勾选用于展示状态流转，不能当作真实来源核验。
